Method and caveats

method

Pipeline

  • Codex: every exec custom tool call parsed as JavaScript; each tools.exec_command / shell_command inside is one record. Exit code from the {"exit_code":n} JSON the cell printed, when it printed it. Model from the turn context.
  • Claude Code: Bash and PowerShell tool_use joined to tool_result by id; failure is is_error or an interrupted result.
  • OpenCode: tool parts from v1 part and v2 session_message, de-duplicated by call id; bash, shell, oc_bash, execute.
  • Cursor: Shell tool-calls joined to results; exit code parsed from text.
  • Dialect, job, embedding form, purpose and failure cause are regex classifiers over command and output text, hand-checked on samples. Expect a few percent noise per cell.

Caveats

  • Harness design dominates. Codex cannot read a file except through a shell or a patch. Compare within a harness, across models.
  • Instructions leak in. All Claude Fable 5.1 sessions carried an auto-mode instruction to prefer Bash. Repo AGENTS.md files push fan-out and specific commands.
  • Host shells differ per harness. Claude's Bash tool is Git Bash; the others land in PowerShell or cmd.exe. Per-model failure rates are not comparable across harnesses.
  • Task mix differs. Cursor and OpenCode sessions were heavier on builds and tests.
  • Hidden failures are a lower bound. Only recognizable error strings count.
  • One user, one machine, July 9 to September 6, 2026.
